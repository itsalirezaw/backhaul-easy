# Backhaul Easy

[English](README.md) · **فارسی**

[![آزمون‌ها](https://github.com/itsalirezaw/backhaul-easy/actions/workflows/ci.yml/badge.svg)](https://github.com/itsalirezaw/backhaul-easy/actions/workflows/ci.yml)

نصب و مدیریت نسخهٔ رسمی [Backhaul](https://github.com/Musixal/Backhaul) با منوی ساده. ابزار نصب و مدیریت توسط **alirezaw** آماده شده است: [گیت‌هاب](https://github.com/itsalirezaw) · [یوتیوب](https://www.youtube.com/@ialirezaw).

این پروژه یک نصب‌کنندهٔ مستقل است. موتور Backhaul از انتشار رسمی دریافت می‌شود و صحت فایل آن با SHA-256 بررسی می‌شود. مخزن پروژه: [itsalirezaw/backhaul-easy](https://github.com/itsalirezaw/backhaul-easy). نتیجهٔ آزمون‌ها و تست‌های عملی باقی‌مانده در [وضعیت اعتبارسنجی](VALIDATION.md) ثبت شده است.

## روش کار

دو حالت در منو وجود دارد:

1. **پنل ثنایی روی ایران:** کاربر به اینباندهای فعلی پنل ایران وصل می‌شود. پنل ترافیک انتخاب‌شده را به یک اوتباند VLESS روی `127.0.0.1:1080` می‌دهد. Backhaul اتصال را به خارج منتقل می‌کند و یک سرویس مستقل Xray که اسکریپت روی خارج نصب می‌کند، ترافیک را وارد اینترنت می‌کند. پورت 1080 قابل تغییر است. ترافیک TCP و UDP کاربران از داخل اتصال VLESS عبور می‌کند.
2. **انتقال پورت:** پورت‌های دلخواه روی ایران به سرویس‌های قابل دسترس از خارج منتقل می‌شوند. پورت مبدأ و مقصد می‌توانند متفاوت باشند و بازهٔ پورت هم قابل تعریف است.

در اصطلاح Backhaul، **ایران Server** و **خارج Client** است. خارج اتصال را به ایران آغاز می‌کند؛ بنابراین اول ایران را نصب می‌کنیم و کد اتصال آن را در خارج می‌چسبانیم. این نام‌ها به نقش Backhaul مربوط‌اند.

هر نصب یک جفت تونل را مدیریت می‌کند و می‌تواند چند پورت را از همان تونل عبور دهد. مسیر پیش‌فرض اینترنت سرور، تنظیمات SSH، قوانین فایروال و تنظیمات عمومی شبکهٔ سیستم تغییر نمی‌کنند. تنظیمات WG Bridge یا پنل به‌صورت خودکار منتقل نمی‌شوند.

## پیش‌نیاز

Ubuntu نسخه‌های LTS برابر 22.04، 24.04 و 26.04 همراه نسخه‌های نقطه‌ای، یا Debian 12/13 با systemd و دسترسی root. معماری‌های amd64 و arm64 و Python 3.10 به بعد پشتیبانی می‌شوند. دسترسی HTTPS به فایل‌های انتشار رسمی لازم است.

اسکریپت پیش‌نیازهای نصب‌نشده را نصب می‌کند. برای نصب دستی:

```bash
apt-get update && apt-get install -y python3 curl ca-certificates openssl iproute2
```

## نصب

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/itsalirezaw/backhaul-easy/main/install.sh)
```

فایل نصب مستقل است و نیازی به کپی بقیهٔ فایل‌های پروژه در سرورها نیست. برای بازکردن مجدد منو:

```bash
backhaul-easy
```

### سرور ایران

1. گزینهٔ **Set up Iran / Outside** و سپس **Iran** را انتخاب کنید.
2. برای سناریوی پنل ثنایی روی ایران، حالت **Panel on Iran** را انتخاب کنید. حالت **Forward ports** برای انتقال معمول پورت است.
3. IP عمومی یا دامنهٔ ایران را وارد کنید؛ خارج باید بتواند به این آدرس وصل شود.
4. روش انتقال را انتخاب کنید. پیش‌فرض TCP است؛ هر هفت روش رسمی در دسترس‌اند. حالت UDP خالص برای اتصال پنل مناسب نیست.
5. پورت ارتباط خود Backhaul را تعیین کنید؛ پیش‌فرض **3080** است. پورت محلی اتصال پنل به تونل، پیش‌فرض **1080**، عدد دیگری است. هر دو قابل تغییرند.
6. مقدارهای پیشنهادی را با Enter نگه دارید یا تنظیمات پیشرفته را باز کنید.
7. خلاصهٔ تنظیمات را بررسی و تأیید کنید. کد اتصال را کامل، همراه **BHE1.**، کپی کنید.

پورت تونل را در فایروال ارائه‌دهنده و سرور ایران باز کنید. برای TCP، WS و روش‌های mux/TLS، پورت TCP لازم است. روش UDP خالص، **هر دو TCP و UDP** همان پورت را نیاز دارد. در صورت امکان دسترسی پورت تونل را به IP خارج محدود کنید. پورت محلی پنل را عمومی نکنید.

### سرور خارج

1. همان فایل نصب را اجرا و **Outside** را انتخاب کنید.
2. کد کامل ایران را وارد کنید. هنگام چسباندن، متن دیده می‌شود.
3. تنظیمات را تأیید کنید. در حالت پنل، سرویس مستقل Xray نصب می‌شود و عبور محلی TCP و UDP از آن بررسی می‌شود. نصب‌های فعلی پنل و Xray دست‌کاری نمی‌شوند.
4. در هر دو سرور `backhaul-easy doctor` را اجرا کنید. روشن‌بودن سرویس یا وجود یک اتصال قدیمی در لاگ، به‌تنهایی اثبات کارکرد ترافیک کاربران نیست؛ تست واقعی پایین را هم انجام دهید.

کد اتصال شامل توکن و در حالت پنل، UUID خروجی است؛ آن را در ویدیو منتشر نکنید. بخش checksum برای تشخیص اشتباه کپی است و رمزنگاری یا امضای هویت نیست. هر کد برای جفت سرور خودش استفاده شود.

## تنظیم پنل ثنایی روی ایران

ابتدا از پنل بکاپ بگیرید. این تنظیمات را خودتان داخل پنل انجام می‌دهید.

### ۱. ساخت اوتباند

روی ایران اجرا کنید:

```bash
backhaul-easy panel
```

JSON نمایش‌داده‌شده را در **تنظیمات Xray → Outbounds → افزودن → JSON** وارد کنید. نام بخش‌ها ممکن است در نسخه‌های مختلف پنل کمی متفاوت باشد.

تگ خروجی `backhaul-out`، پروتکل `vless` و آدرس آن `127.0.0.1` با پورت محلی انتخاب‌شده است. UUID همان مقدار تولیدشده باقی بماند. این پورت **VLESS است و SOCKS5 نیست**.

تنظیمات قدیمی وایرگارد مانند `sendThrough: 10.204.0.2` یا `interface: wgb-exit` را روی این خروجی نگذارید. اگر ثنایی داخل Docker است، برای دسترسی به آدرس محلی میزبان باید از شبکهٔ host استفاده کند؛ این راهنما نصب مستقیم یا شبکهٔ host را فرض می‌کند.

### ۲. هدایت اینباندها

در Routing یک قانون اضافه کنید که **Inbound tags** آن، تگ واقعی اینباندهای کاربران باشد و **Outbound tag** برابر `backhaul-out` قرار بگیرد. این قانون باید قبل از قانون‌های کلی‌ای باشد که همان کاربران را به `direct` می‌فرستند. قانون API و مسدودسازی‌های عمدی را حفظ کنید.

بالابردن ترتیب اوتباند، قانون مستقیم موجود در Routing را لغو نمی‌کند. نمونهٔ قانون زیر را به `routing.rules` اضافه کنید و جای عبارت نمونه، تگ واقعی اینباند را بگذارید:

```json
{
  "type": "field",
  "inboundTag": ["YOUR_ACTUAL_USER_INBOUND_TAG"],
  "outboundTag": "backhaul-out"
}
```

برای چند اینباند، تگ همهٔ اینباندهای موردنظر را در همین فهرست قرار دهید. تگ اینباند، نام آن در تنظیمات Xray است؛ نام کاربر، UUID یا شمارهٔ پورت نیست. `routing.domainStrategy` را معمولاً روی `AsIs` نگه دارید، مگر اینکه عمداً به مسیریابی مبتنی بر IP نیاز داشته باشید.

### ۳. DNS پنل

برای DNS داخلی Xray، این شیء را در بخش `dns` قرار دهید. اگر DNS اختصاصی و ضروری دارید، آن تنظیمات را آگاهانه ادغام کنید:

```json
{
  "tag": "backhaul-dns",
  "queryStrategy": "UseIPv4",
  "servers": ["8.8.8.8", "1.1.1.1"]
}
```

سپس این قانون را قبل از قوانین مستقیم مرتبط، در Routing اضافه کنید:

```json
{
  "type": "field",
  "inboundTag": ["backhaul-dns"],
  "outboundTag": "backhaul-out"
}
```

آدرس‌های عددی بالا از UDP پورت 53 استفاده می‌کنند. تگ DNS باعث می‌شود درخواست‌های DNS داخلی Xray هم به خارج برسند. این کار DNS کل سیستم‌عامل را تغییر نمی‌دهد. وقتی هدف عبور DNS از خارج است، fallback از نوع `localhost` یا local-mode نگذارید. برنامهٔ کاربر هم ممکن است تنظیم DNS مستقل داشته باشد؛ به همین دلیل تست با کلاینت واقعی لازم است. [مستندات DNS](https://xtls.github.io/en/config/dns.html) و [Routing](https://xtls.github.io/en/config/routing.html) در پروژهٔ Xray.

### ۴. ذخیره و تست

تغییرات را ذخیره و هستهٔ Xray پنل را ری‌استارت کنید. یک کاربر واقعی را دوباره وصل کنید. IP خروجی باید IP سرور خارج باشد. چند سایت را باز کنید و ویدیو پخش کنید. افزایش مصرف کاربر را هم در ثنایی ببینید. آدرس داخل کانفیگ کاربر همچنان ایران می‌ماند.

اگر تونل قطع شود، ترافیک کاربران انتخاب‌شده باید قطع شود و خودکار به خروجی مستقیم برنگردد؛ برای این رفتار، direct را به‌عنوان fallback یا عضو جایگزین balancer تعریف نکنید.

## روش‌های انتقال و تنظیمات پیشرفته

- **TCP:** انتقال اتصال TCP؛ در حالت انتقال پورت، گزینهٔ `accept_udp` برای عبور UDP داخل TCP هم وجود دارد.
- **TCPMux:** انتقال TCP با multiplexing.
- **UDP:** فقط ترافیک برنامه‌های UDP؛ اتصال کنترل همچنان TCP است.
- **WS و WSMux:** انتقال TCP با WebSocket، بدون یا همراه multiplexing.
- **WSS و WSSMux:** همان WebSocket با TLS. ساخت گواهی self-signed از داخل منو یا استفاده از فایل PEM موجود ممکن است.

در حالت پنل، UDP کاربران داخل اتصال VLESS قرار می‌گیرد؛ بنابراین شش روش مبتنی بر TCP قابل استفاده‌اند. سرعت و رفتار آن الزاماً مشابه UDP مستقیم نیست.

تنظیمات پیشرفته شامل pool، retry، keepalive، heartbeat، channel، mux، بافر سوکت و MSS، PROXY protocol در روش‌های پشتیبانی‌شده و مانیتورینگ است. تنظیمات مشترک mux باید در دو سرور سازگار باشند. PROXY protocol فقط برای برنامهٔ مقصد سازگار است و در حالت پنل خاموش می‌ماند.

مانیتورینگ به‌صورت پیش‌فرض خاموش است؛ ابزار مانیتورینگ رسمی بدون احراز هویت و روی آدرس عمومی گوش می‌دهد و فعال‌کردن آن تأیید صریح و محدودسازی فایروال می‌خواهد. بهینه‌ساز عمومی شبکه و pprof غیرفعال‌اند. آدرس مقصد انتقال پورت باید IPv4 یا دامنه باشد؛ parser نسخهٔ رسمی 0.7.2، IPv6 مستقیم مقصد را پشتیبانی نمی‌کند. سقف این نصب‌کننده 128 نگاشت پورت است.

**امنیت انتقال:** TCP، TCPMux، WS و WSMux لایهٔ TLS اضافه نمی‌کنند و VLESS تولیدشده هم رمزنگاری اضافه ندارد. HTTPS کاربر، TLS خودش را حفظ می‌کند. در نسخهٔ رسمی Backhaul v0.7.2، کلاینت WSS از `InsecureSkipVerify` استفاده می‌کند؛ انتقال رمز می‌شود اما هویت گواهی سرور تأیید نمی‌شود. این ابزار را هم‌ارز امنیت WireGuard یا تضمین مقابله با فیلترینگ معرفی نکنید. [کد رسمی اتصال TLS](https://github.com/Musixal/Backhaul/blob/v0.7.2/internal/utils/network/ws_dialer.go).

## مدیریت و حذف

```bash
backhaul-easy status
backhaul-easy doctor
backhaul-easy logs
backhaul-easy start
backhaul-easy stop
backhaul-easy restart
backhaul-easy ports
backhaul-easy advanced
backhaul-easy pairing
backhaul-easy panel
backhaul-easy upgrade
backhaul-easy uninstall
```

برای حذف باید `REMOVE` تایپ کنید. فقط سرویس‌ها و فایل‌های متعلق به همین ابزار حذف می‌شوند. فایل‌های تغییریافته حفظ می‌شوند یا برای بررسی دستی گزارش می‌شوند؛ وابستگی‌ها و سرویس‌های دیگر حذف نمی‌شوند. اوتباند و Routing که دستی در پنل اضافه کرده‌اید نیز باید دستی اصلاح شوند.

برای نصب نسخهٔ جدید، فایل نصب جدید را دریافت و با `bash install.sh --upgrade` اجرا کنید. گزینهٔ repair منو فقط نسخه‌های داخل فایل نصب فعلی را دوباره نصب می‌کند. نسخهٔ نصب‌شدهٔ فایل در `/usr/local/lib/backhaul-easy/install.sh` است. گزینهٔ `--check` دریافت و صحت فایل رسمی را بدون نصب بررسی می‌کند و پیش‌نیازها باید از قبل موجود باشند. `--no-menu` ابزارها را بدون ساخت تونل نصب می‌کند.

## وضعیت آزمون و مجوز

نسخه‌های انتخاب‌شده: Backhaul **v0.7.2** و Xray **v26.3.27** برای خروجی خارج. نتیجهٔ آزمون‌هایی که واقعاً اجرا شده‌اند در [VALIDATION.md](VALIDATION.md) نوشته می‌شود. قبول‌شدن نسخهٔ سیستم‌عامل در نصب‌کننده به معنی تست‌شدن همهٔ ترکیب‌های سیستم‌عامل و معماری نیست.

Backhaul متعلق به Musixal و مشارکت‌کنندگان آن با مجوز AGPL-3.0 و Xray-core متعلق به XTLS و مشارکت‌کنندگان با مجوز MPL-2.0 است. نصب‌کننده نیز با مجوز AGPL-3.0 ارائه می‌شود. [LICENSE](LICENSE) · [THIRD_PARTY.md](THIRD_PARTY.md).
